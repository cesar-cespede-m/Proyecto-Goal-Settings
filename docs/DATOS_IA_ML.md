# Datos, IA y ML

## Datos

La aplicación acepta datos tabulares CSV en un entorno local. Antes de analizarlos se debe comprobar procedencia, permiso de uso, estructura, valores ausentes, sesgos e identificadores personales. En este repositorio sólo se usan datos sintéticos, sandbox o anonimizados con autorización. Los datasets de demostración no representan a Babel.

Cada cálculo que sustente una decisión de diseño debe conservar definición, filtros, fecha, versión de datos y limitaciones. Una asociación o una predicción no demuestra causalidad.

## IA generativa

La IA puede ayudar a formular preguntas, proponer pasos y explicar resultados. El sistema valida estructuras y cifras con herramientas acotadas. La persona revisa el contexto que se envía, decide qué recomendaciones acepta y conserva la responsabilidad de aprobar. Sin proveedor activo, el producto usa reglas y plantillas.

No enviar información interna ni datos personales a un proveedor sin autorización. No presentar texto generado como medición observada.

## ML tradicional

Cuando la pregunta requiere anticipar un resultado conocido, el motor entrena modelos supervisados. El proceso debe separar entrenamiento, validación y prueba; ajustar transformaciones sólo con entrenamiento; excluir columnas posteriores al evento; comparar con una referencia simple; y reservar una evaluación final no usada para elegir el modelo.

La aprobación humana del plan precede al entrenamiento. Otra revisión precede a la publicación o uso del resultado. El LLM no entrena ni sustituye al modelo estadístico.

## Aplicación al objetivo anual

El ML es opcional: primero se define la decisión de diseño y el indicador. Se usa sólo si una predicción aporta evidencia útil. Para el objetivo anual, la evidencia debe distinguir demostraciones sintéticas, observaciones reales autorizadas y propuestas pendientes.
